# Focus Matrix 开源持续维护机制设计

日期：2026-10-23，Asia/Shanghai。状态：待范围确认，未实施自动化。

目标：让开源后的安全问题、依赖变化、数据保护回归和用户反馈有持续检查、负责人、
处理期限与可核验的关闭条件。保留现有 Windows 发布验收，不把扫描报告等同于安全认证。
依据：[本轮审计](../../security/open-source-audit-20261023.md)。

## 范围与约束

- 沿用现有 GitHub Actions、npm/Cargo 锁文件和 Windows 正式构建流程。
- 本轮只实施维护文件和检查，不升级真实安装版、不部署云端、不改数据格式或生产凭据。
- 每次修改前后执行 `npm run version:save`，保留历史、标签和源码 ZIP；不覆盖旧 Release。
- 涉及真实本地数据或本机安装更新时仍先备份，并使用 `install-local.ps1`。
- 不自动合并依赖，不自动购买签名服务，不在公开日志中输出凭据或真实任务。
- 默认由 keykonor 负责分诊与合并；下面的频率、工具与时限是本设计提出的默认值，尚非用户另行指定。

## 维护频率与责任

| 时机 | 自动检查/人工动作 | 结果与处理 |
| --- | --- | --- |
| 每个 PR、main 提交 | 当前公开源码检查、历史秘密扫描、前端/原生/数据保护回归；npm/Rust 安全检查 | 在提交显示独立状态；失败保留为失败，修复后重跑 |
| 每周一 09:00 北京时间 | 根项目和网站 npm 审计、RustSec 审计、JS/TS CodeQL；保留扫描摘要 | 周一查看失败和新增告警，分诊后归入整改记录 |
| 每周二 09:00 北京时间 | Dependabot 检查根 npm、cloud-site npm、Cargo、GitHub Actions | 只提 PR；补丁/次版本分组，大版本独立，限制同时打开数量 |
| 每次发布 | 现有完整 Windows 检查、对应目标依赖安全门禁、安装与字节保留验收、哈希与来源 | 检查通过且维护者明确发布后才发布；不复用其他提交的“绿灯” |
| 每月首周 | 人工复核未关闭安全项、许可证/SBOM、图标、文档、Windows 真机与备份恢复 | 将日期、负责人、证据和下次动作写入维护记录 |
| 每季度 | 撤权/离线/冲突专项，Android 与多屏/缩放回归，账号和发布权限检查 | 使用隔离数据；生产检查单独记录，不伪造恢复结论 |

GitHub cron 采用 UTC：每周一 01:00 UTC 对应北京时间 09:00；调度可能延迟。
执行器休眠或 GitHub 定时任务暂停时不能保证准点，维护者需月度核对最近成功运行时间。
不额外建立每天发送“无变化”通知的提醒。

## 拟落地的仓库文件

| 文件 | 职责 |
| --- | --- |
| `.github/dependabot.yml` | npm 根目录与 cloud-site、`src-tauri` Cargo、根 GitHub Actions 周度更新；不配置自动合并 |
| `.github/workflows/maintenance.yml` | PR/main/周一/手动审计，根与网站分开的 npm jobs、RustSec 和当前源码检查；JSON 摘要保留 30 天 |
| `.github/workflows/codeql.yml` | JS/TS 分析，包含桌面、网站、网关与服务端源码；PR/main/周度；只在需要的 job 授予 security-events 写权限 |
| `.github/workflows/secrets.yml` | 使用固定版本工具扫描可达 Git 历史并脱敏；PR 不读取生产秘密；不上传原始秘密结果 |
| `.github/workflows/release-windows.yml` | 普通提交与实际发布分别校验；接入同一提交的桌面安全检查，让标签/手动发布都等待门禁 |
| `CONTRIBUTING.md` | 干净环境、测试、合成数据、提交审查与升级保护规则 |
| `.github/ISSUE_TEMPLATE/bug_report.yml` | 版本、Windows/WebView2、复现、预期/实际；明确禁止真实数据和分享链接 |
| `.github/ISSUE_TEMPLATE/feature_request.yml` | 用户场景、期望和验收，不要求上传任务文件 |
| `.github/pull_request_template.md` | 变更原因、数据兼容、验证证据、权限/依赖/许可影响和回退方法 |
| `SECURITY.md` | 支持范围、私密报告方式、脱敏要求与初步响应目标；入口未启用时诚实标记 |
| `docs/MAINTENANCE.md` | 周/月流程、紧急分诊、发布/回退、例外到期管理和运行检查方法 |
| `README.md` | 链接维护、安全和贡献文档；徽章只链接实际已启用的流程 |

实施由当前助手在本会话内完成，结束前安排一位独立审阅者核对差异和证据。
实现时选择官方维护的工具、核对准确 Action SHA，不猜版本，不引入付费服务依赖。

## 工作流的安全边界

- Action 固定完整提交 SHA，依赖升级由 Dependabot 提议；最低所需 token 权限，checkout 不保留凭据。
- 使用 `pull_request`，不以高权限 `pull_request_target` 执行外部贡献的代码。
- 包名、分支名、PR 标题等不直接拼入 shell；无需使用的生产秘密一律不传给检查。
- npm 审计检查开发依赖和运行依赖；根项目与 cloud-site 独立展示，后者不能被“根项目 0 漏洞”掩盖。
- 安全数据库无法访问、工具下载失败、结果缺失属于扫描失败，不允许 `continue-on-error` 冒充通过。
- Rust 公告逐项标注维护状态、目标平台与实际调用路径。停止维护提示进入维护债务表，不能统称可利用漏洞。
- 每个例外记录公告 ID、平台/路径、理由、负责人、到期日和复核证据；不按包名全局永久忽略。
- 云端当前已有严重/高危依赖，初次网站审计预期会失败；自动化不以新增忽略项制造绿灯。

## 发布门禁与现有流程的关系

桌面发布必须等待同一提交的桌面源码/依赖安全检查和原有 Windows 安装数据保留检查。
安全检查需实现为可被发布流程调用的工作流（`workflow_call`）或该流程内的 job，
`publish.needs` 必须包含对应安全门禁，不能只依赖另一个独立流程的徽章或上次运行。
标签推送与手动发布都运行此门禁，安全 job 失败、取消或未完成均不得发布。
网站发布必须等待网站审计及其构建、权限、撤销和隔离回归。两类目标分别判断风险：
没有证据进入 Windows 产物的网站开发依赖，不直接宣称桌面程序受相同漏洞影响。

GitHub 的检查状态不自动等于强制保护。首次工作流通过后，管理员再核对 main 的必需检查、
禁止强推/删除和版本标签规则。传统保护接口本次 403，不能自动宣称管理设置已生效。
如果当前连接不能管理设置，在维护手册给出准确界面步骤和应核对的检查名。

不通过本机制改变 `v0.2.0` 已发布标签或安装包，也不因为维护文档提交而自动发新版。
当前流程对普通 PR/main 也将默认 `v0.2.0` 与当前 SHA 比较，会拒绝发布后的新提交。
实施时把这一相等性检查限制到实际发布事件；普通提交仍校验源码元数据一致性。
保留实际发布时标签已存在且指向其他提交就拒绝的规则，不能以移动标签解决普通 CI 误失败。

## 问题处理与关闭

| 级别 | 处理目标（维护目标，不是服务承诺） | 关闭证据 |
| --- | --- | --- |
| P0：已确认密钥暴露/可利用生产漏洞/数据破坏 | 发现后立即止损，尽量 24 小时内形成处置记录 | 撤销或隔离依据、修复、针对复现的回归、受影响版本说明 |
| P1：严重/高危公告待分诊、数据保护失败、关键检查失效 | 2 个工作日内确认影响与责任人，7 天内修复或说明具体排期 | 更新后的准确版本、扫描结果、对应目标回归或有期限的风险接受 |
| P2：加固、未维护依赖、许可证与签名治理 | 月度复核并安排 | 证据、复测、文档和必要的发布记录 |

私密漏洞不发公开 Issue；启用并核验私密报告后再对外提供入口。普通故障使用合成数据。
公开整改记录可描述依赖公告，但不附实际凭据、用户数据或未修复的敏感复现材料。

## 验收与状态记录

1. 修改前后都有不可覆盖源码快照，用户数据与已发布产物未改。
2. YAML 能由解析器读取，事件、权限、工作目录、锁文件路径及固定 SHA 经检查。
3. 干净环境 `npm ci` 后版本与锁文件一致；执行现有必要检查，不能把重复工作目录算成加倍测试覆盖。
4. 用合成凭据样本验证秘密扫描失败且不回显内容；不拿真实密钥测试。
5. 核对不安全依赖确实使对应审计 job 失败；网络失败也不能通过。
6. 推送后记录首次 GitHub 实际运行链接；静态校验不能代替 CodeQL/RustSec/定时任务实际执行。
7. 分别记录：方案已批准、配置已提交、配置已推送、首次扫描已执行、管理设置已核验。
8. 验证普通提交在既有 v0.2.0 标签存在时仍可运行 CI；验证标签和手动发布均不会跳过失败的安全门禁。

当前状态：审计和设计文档已编写；实施范围的确认仍在等待，未创建工作流或更改远端设置。
