# 云端同步启动审查与修复（2026-10-09）

## 根因与证据

已确认是状态判断和错误展示存在缺陷；本次未能稳定复现用户报告的持续启动故障，因此不能把具体的一次配置读取失败原因当作已证实。

- `src/components/CloudShareModal.tsx` 原先仅用 `!status.configured` 显示“云端尚未配置，请使用已安装的版本”。
- `src/hooks/useCloudSharing.ts` 的初始状态就是 `configured:false`，启动后才异步读取。读取失败时仅写入 `status.error`，而弹窗把错误放在 `configured:true` 分支中，导致实际错误被隐藏。
- 原重试同步先保存本地内容，未单独重试启动配置读取；本地保存失败也可能延迟配置恢复显示。
- Rust 原先用 `Path.exists()` 判定凭据不存在，这个方法也会把文件访问错误折叠成不存在。现已直接读取文件，只有 `NotFound` 才认定缺失。
- 实际安装文件与旧目录中的启动文件哈希一致，未发现错误安装版本。受控重启后原安装版返回 `configured:true`、无错误，手机页面正常打开。
- 本机主凭据和上一份加密凭据均可由当前 Windows 用户 DPAPI 解密，写入密钥与本地服务端部署配置一致。没有更换或重新生成凭据。

- 桌面通过 Tauri Rust 命令访问后端，按 Windows 系统代理联网。任务和日期备忘录进入同步，设置、窗口状态及本地历史不上传。
- 公开地址来自 `cloud-site/lib/publicCloudConfig.json`，Rust 编译时内嵌同一配置。当前 API 为 `https://matrix-d4ggytzjuc8ad872a-1323076267.ap-shanghai.app.tcloudbase.com`。
- 服务端使用 `TCB_ENV`、`PUBLIC_ORIGIN`、`CLOUDBASE_API_KEY`、`FOCUS_MATRIX_WRITE_TOKEN`；本地部署配置被 Git 忽略，未复制到前端。

## 最小修复

1. 区分配置加载中、读取失败、凭据缺失和浏览器预览，显示原始读取错误并提供重试。
2. 配置未读取成功时，先重试读取，再保存和同步；返回的配置与设备缓存先显示，后续内容落盘失败也不会隐藏它们。
3. 本地配置加载与云端连接成功分开显示。同步成功后才显示连接正常。
4. 区分连接超时、连接建立失败、HTTP 401/403/404/5xx 和非 JSON 响应。设备列表失败时保留缓存并返回真实错误。
5. 保持原有存储格式、DPAPI 加密、账户密钥、同步确认顺序及历史保存流程。
6. 将 Vitest 范围限定为 `src`，避免误收集使用 Node 测试框架的源码归档测试；后者继续由 `npm run version:test` 执行。
