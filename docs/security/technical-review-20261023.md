| 问题 | 原行为与复现 | 修正与证据 |
| --- | --- | --- |
| 初始加载期间输入被覆盖 | 暂停 `read_local_data`，原矩阵可添加任务；读取返回后覆盖新任务 | 未就绪/读取失败保持交互锁，修改回调同时检查同步 ref；真实组件浏览器回归验证 |

| 退出保存期间编辑未落盘 | 暂停退出前的提交，继续输入；旧快照落盘后直接退出 | 退出开始同步锁住编辑，重复事件只退出一次；保存失败保留内容并解锁重试，更新 nonce 协议保留 |
| 旧发布标签阻断普通 CI | 旧 v0.2.0 指向 34af03c，普通提交 SHA 不同，原校验必抛错 | 仅实际标签/手动发布执行严格版本及 SHA 检查；普通 PR/分支检查不受旧标签影响；10 个隔离回归通过 |
| 新标签检查遗留非零退出码 | 用 `show-ref` 检查不存在的新标签会留下 LASTEXITCODE=1，Actions wrapper 会误判失败 | 用零退出的精确引用枚举；回归使用与 Actions 一致的退出包装验证新标签通过 |
| 测试重复收集旧工作树 | 原 `vitest run src` 同时匹配 outputs 里的 src，37 项变成74项 | 独立 Vitest include 只收集根 src；放入故意失败的 outputs 探针仍只收集9文件、37项 |
| 用户数据路径漏检 | 隔离 fixture 强制跟踪假任务/窗口/更新文件，原公开源码检查通过 | 快照和公开源码检查共用私密路径策略；11 项回归验证拒绝、脱敏和 ignored 文件不被公开扫描读取 |
